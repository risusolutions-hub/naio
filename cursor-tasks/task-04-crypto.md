# Task 04 — niao_crypto: sha2, hmac, jwt (replace sha2, hmac, jsonwebtoken)
Read MASTER_PLAN.md first. NOTE: hashes/MACs are safe to implement (well-specified, no secret-dependent branching needed beyond constant-time compare). We still do NOT reimplement TLS — rustls stays.

## Build
Create `crates/niao_crypto` (zero deps):
- SHA-256/SHA-512 (FIPS 180-4), incremental Digest API.
- HMAC over both.
- constant-time eq.
- JWT: HS256/HS512 sign+verify, exp/nbf/iat validation, base64url via niao_codec. Reject alg=none. RS256 NOT included — if ahiru_core uses RS256, keep jsonwebtoken there and say so in the report.

## Wire up
- Replace sha2 in niao_pkg (checksums) and ahiru_core; hmac + jsonwebtoken in ahiru_core auth.
- Expose to Niao: crypto.sha256(), crypto.hmac(), ahiru JWT middleware unchanged externally.

## Acceptance
- NIST test vectors for SHA-256/512; RFC 4231 HMAC vectors; JWT interop test against tokens generated by the old crate (fixture strings).
- Bench: within 10% of sha2 crate on 100MB stream.

## Ground rules (apply to EVERY task)
- ZERO new third-party crates. Only std + existing niao_* workspace crates.
- Lightweight & fast: no allocations in hot loops, prefer &str/&[u8], pre-size Vecs, add #[inline] on small hot fns.
- Public API surface goes to Niao programs via niao_runtime builtins + a niao_libs/<name>/ module (Niao-language wrapper), mirroring how niao_libs/json works today.
- Add unit tests in the crate + at least one .niao example under examples/.
- Add/extend a benchmark under benchmarks/ comparing before vs after.
- After changes: `cargo check --workspace` then `cargo test --workspace` must pass.
- Remove the replaced third-party dependency from every Cargo.toml that used it, and confirm it disappears from `cargo tree`.
- Update CHANGELOG.md with one line.
